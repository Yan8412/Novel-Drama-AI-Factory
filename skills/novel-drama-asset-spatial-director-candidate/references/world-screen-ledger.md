# Per-instance world and screen ledger

The spatial owner already controls reference roles and topology proposals. Extend only a review sidecar, using the candidate `qa_feedback.py` evidence interfaces alongside existing lifecycle checks. Do not replace the asset registry, accepted reference bindings or installed spatial schema.

Track each prop instance separately. Keep approved world requirements (identity, fixed base, height, persistence and disturbance where specified) apart from screen observations (visible region, last visible frame, first absent frame, original PTS and any measured projection). Record an assumption as an assumption; a model coordinate is not a measured world coordinate.

An unseen object has unknown world visibility mechanism unless evidence establishes a compatible exit or occluder. Do not convert `UNSEEN` into physical disappearance, retraction or restoration; do not convert a plausible offscreen story into PASS. A substantial visible tip followed by absence requires its own discontinuity finding, even if another prop appears to exit the frame.

For a proposed explanation, retain the image registration, uncertainty range, camera/landmark behavior and endpoint/opening-frame coverage that supports it. A positive pixel margin without an empirical error bound remains `UNVERIFIED`. Keep design readability windows separate from observed video timing; a local projection margin is not a safety proof.

Preserve frozen start/end reference roles, the locked following shot and the existing shot QA contract. A compatible character seam cannot waive prop continuity. No asset creation, derivative endpoint, upload, provider mode change or production-state update follows from completing this ledger.
