# Candidate Skill integration

Four isolated overlays live under `skills/` with `-candidate` names. They are not copied into an active discovery directory, installed, promoted, or wired into production. Their wording is newly authored from the reviewed responsibility boundaries; private project source and prompts are not bundled.

| Candidate | Retained owner | Narrow addition |
|---|---|---|
| Prompt optimizer | Evidence classification, routing, HEP handoff | Separate missing instructions from present-but-failed output; route only from matching upstream evidence; byte-level source/effective review. |
| Cinematic video director | Timing, camera and action intent | Persistent-object visibility and observable contact/support transition review. |
| Character performance director | Acting and reactions | Distinguish awareness, temporal sequence and causal response; retain natural identity detail and silent-shot behavior. |
| Asset spatial director | Reference roles and geometry | Require projection/occlusion evidence, preserve unknown depth and stable facial detail, check adjacent boundary views. |

## Accepted interfaces remain authoritative

The reviewed installation uses `DIRECTOR_INTENT`, `PERFORMANCE_INTENT`, and `SPATIAL_INTENT` as proposal schemas. Extra audit metadata stays in a sidecar. The optimizer owns the handoff through `HUMANIZED_EXECUTION_PLAN -> GenerationRecipe + ProviderProfile`; accepted Compiler 1.5.1 owns its existing structured-contact compilation and validation.

The opt-in `integration.review_compiled_candidate` interface consumes already produced Compiler 1.5.1 results and supplied source/effective/request data without importing or executing production modules. It does not install a runtime hook, recompile frozen text, or dispatch a request. Its `mode_router`, `motion_contract`, and `prompt_candidate` modules are offline supplementary interfaces. In particular, supplied provenance points to upstream verification and cannot authenticate itself; static findings do not prove real motion, story interpretation, or production admission. Missing installed schemas/inputs means the production handoff remains unavailable, not an invitation to infer them.

## Validation scope

The skill-creator `quick_validate.py` checks candidate frontmatter, naming and scaffolding. Run it separately for each of the four directories. Read the actual report for results; a successful structural validation does not establish automatic discovery, live skill routing, semantic quality, macOS execution or real video quality.

Changes to prompt/router code are validated by the package's offline tests. The original production Skill manifests and evaluation history remain untouched; these overlays do not claim to rerun those historical semantic evaluations. Further production promotion and any generation experiment require their own authorization.

Structural validation performed locally: all four candidate Skills passed the bundled `quick_validate.py` under an existing Python 3.13 environment with PyYAML. Six local reference links resolved inside this candidate tree. These checks do not establish semantic evaluation or production activation. Exact validation logs and local evidence remain outside the published repository.
